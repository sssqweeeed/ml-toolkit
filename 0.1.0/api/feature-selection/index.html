    Feature selection¶

    Selectors choose input columns using training and validation pools. A ranker scores columns of an already fitted adapter; RFE and Top-K use that ordering. The final model is fitted with the last validation split's selected columns.

    Prepare a selection experiment¶

    Run from an installed checkout after python -m examples.prepare_data --dataset bike. The imported prepare_training() loads the original Bike Sharing hours, model parameters and local MLflow settings described in the training example. Targets are rentals per hour; weights are one per recorded hour.

    from examples.training_setup import prepare_training
from ml_toolkit import train_model
from ml_toolkit.metrics import metrics_frequency
from ml_toolkit.models import CatBoostLogLinkRegressionModel
from ml_toolkit.training import Holdout

data, params, config = prepare_training()
splitter = Holdout(data, val_size=0.25, test_size=0.2)
from ml_toolkit.feature_selection import (
    ForwardSelector,
    RFESelector,
    TopKSelector,
)
from ml_toolkit.training import importance_ranker

    Choose a selector¶

    The selector owns its settings and ranker. Run the setup above first. Omit feature_selector to keep all columns. Each validation window uses fresh models, and the final fit reuses the last window's selected columns.

    partition = next(splitter.get_validation())
selectors = (
    RFESelector(
        min_features=3,
        metric="mean_poisson_deviance",
        direction="minimize",
        ranker=importance_ranker,
        max_fits=2,
    ),
    TopKSelector(k=3, ranker=importance_ranker),
    ForwardSelector(
        metric="mean_poisson_deviance",
        direction="minimize",
        max_features=2,
        max_fits=21,
    ),
)
for selector in selectors:
    selection = selector.select(
        train=partition.train,
        validation=partition.heldout,
        params=params,
        model_factory=CatBoostLogLinkRegressionModel,
        metric=metrics_frequency,
    )
    print(
        type(selector).__name__,
        "features:",
        len(selection.features),
        "candidates:",
        len(selection.steps),
    )

    RFESelector features: 11 candidates: 2
TopKSelector features: 3 candidates: 2
ForwardSelector features: 2 candidates: 21

    RFE repeatedly removes low-ranked columns and chooses the smallest visited subset within score_tolerance of the best result. Top-K ranks once and keeps exactly k, including protected features, even if its quality is worse. Forward compares every remaining single-feature addition and accepts it only when the absolute gain exceeds min_improvement (default zero). It does not begin a round that exceeds max_fits; too little budget for its first comparison is an error. With no protected columns it starts by comparing every singleton.

    protected_features are mandatory and count toward every size limit. Ties prefer the original feature order. steps contains all evaluated candidates, including rejected ones, with metrics and timings; selected_step identifies the returned subset. No fitted models are retained. settings records concrete JSON-compatible configuration; executable rankers are excluded. Its public type, ml_toolkit.feature_selection.SelectionSettings, is a flat dictionary with string keys and values of type str, int, float, bool, None, or tuple[str, ...]. Use it for a custom selector's configuration; the tuple form records feature names.

    Each validation run stores concrete settings and every evaluated subset in selection/history.json, including scores, timings, available importances and selected_step. The selected scores are logged under selection/metrics/<name>; fit count, feature count and selected index have separate selection/ entries.

    Implement a selector¶

    Implement FeatureSelector.select with the documented keyword arguments and return a FeatureSelectionResult. The workflow checks the selected history entry and input-column order. Create a fresh model for every fit, copy parameter dictionaries, and keep learned state local to each call. The same selector instance is reused across splits; it must not accumulate fitted estimators.

    This reusable example evaluates a project-approved feature subset:

    Complete custom selector source 
    """A project-owned selector that evaluates an approved feature subset."""

from collections.abc import Callable
from dataclasses import dataclass
from time import perf_counter

import numpy as np

from ml_toolkit import Pool
from ml_toolkit.feature_selection import FeatureSelectionResult, FeatureSelectionStep
from ml_toolkit.metrics import Metric
from ml_toolkit.models.base import Model
from ml_toolkit.types import ModelParams


@dataclass(frozen=True)
class FixedFeatureSelector:
    """Evaluate a nonempty, unique subset, preserving original input order."""

    features: tuple[str, ...]

    def select(
        self,
        *,
        train: Pool,
        validation: Pool,
        params: ModelParams,
        model_factory: Callable[[ModelParams], Model],
        metric: Metric,
    ) -> FeatureSelectionResult:
        """Fit and evaluate the subset; retain no learned state between calls."""
        if not self.features or len(set(self.features)) != len(self.features):
            raise ValueError("features must be nonempty and unique")
        if not set(self.features) <= set(train.X.columns):
            raise ValueError("Requested features must exist in training data")
        names = tuple(name for name in train.X.columns if name in self.features)
        train = train.select_features(names)
        validation = validation.select_features(names)
        started = perf_counter()
        model = model_factory(params.copy()).fit(train, validation)
        fit_seconds = perf_counter() - started
        started = perf_counter()
        prediction = model.predict_pool(validation)
        if prediction.shape != (len(validation),) or not np.isfinite(prediction).all():
            raise ValueError("Predictions must be finite and aligned")
        scores = dict(
            metric(
                validation.y.to_numpy().astype(float),
                prediction,
                validation.weight.to_numpy().astype(float),
            ).to_dict()
        )
        step = FeatureSelectionStep(
            names,
            scores,
            {},
            (),
            fit_seconds,
            perf_counter() - started,
            0.0,
            model.best_iteration,
        )
        return FeatureSelectionResult(
            names, 0, (step,), {"selector": "fixed", "features": names}
        )

    from examples.custom_selector import FixedFeatureSelector

custom_selection = train_model(
    splitter=splitter,
    params=params,
    model_factory=CatBoostLogLinkRegressionModel,
    metric=metrics_frequency,
    run_name="custom-selector",
    config=config,
    feature_selector=FixedFeatureSelector(("temperature", "hour")),
)
print(custom_selection.features)
assert custom_selection.feature_selection is not None
print(custom_selection.feature_selection.settings)

    ('temperature', 'hour')
{'selector': 'fixed', 'features': ('temperature', 'hour')}

    The normal workflow performs validation, optional tuning and a fresh final fit using those columns. Prediction, refitting and model packaging remain the model adapter's responsibility: serve inputs in result.features order through that adapter. The selector itself owns no learned model state and is not a serving artifact. See model packaging for saving and reloading the final model. Custom selectors must use the supported Pool and Model contracts; they do not extend backend or prediction-shape support.

    The selected final model can be packaged and checked independently of the selector. Continue with custom_selection above; this creates an MLflow model artifact and verifies its reloaded predictions on the selected input schema.

    import numpy as np
import mlflow

development = splitter.get_test()
assert development.heldout is not None
selected_train = development.train.select_features(custom_selection.features)
selected_test = development.heldout.select_features(custom_selection.features)
expected = custom_selection.model.predict_pool(selected_test)
with mlflow.start_run():
    logged = custom_selection.model.log(selected_train)
model_info = logged[1] if isinstance(logged, tuple) else logged
reloaded = mlflow.pyfunc.load_model(model_info.model_uri)
np.testing.assert_allclose(
    reloaded.predict(selected_test.to_model_input(categorical_as_strings=True)),
    expected,
)
print("Selected model predictions preserved after reload")

    Selected model predictions preserved after reload

    Choose a ranker¶

    Ranker What its score means
    importance_ranker Importance supplied by the fitted adapter's native backend
    ShapRanker Weighted mean absolute native raw-output SHAP contribution
    Custom callable Your score for each current validation column

    ShapRanker supports CatBoost and LightGBM and does not require the shap extra. It samples positive-weight validation rows deterministically. Native raw outputs may have different units from adapter predictions.

    from ml_toolkit.training import ShapRanker

shap_selection = TopKSelector(
    k=3, ranker=ShapRanker(max_samples=500, seed=42)
).select(
    train=partition.train,
    validation=partition.heldout,
    params=params,
    model_factory=CatBoostLogLinkRegressionModel,
    metric=metrics_frequency,
)
print("SHAP-selected features:", shap_selection.features)

    SHAP-selected features: ('temperature', 'feels_like_temperature', 'hour')

    The selected names retain their original input order. SHAP affects ranking; the candidate subset is still evaluated with the supplied task metric.

    Implement a ranker¶

    A FeatureRanker is callable as ranker(model, data). The model is already fitted; data contains the current validation columns. Return exactly one finite value per column name. Higher values rank higher, and signed values are allowed. Preserve both inputs and retain no learned state between calls.

    This custom ranker measures the increase in weighted validation MAE after permuting one feature. A fresh seeded generator makes repeated calls reproducible. Each perturbation starts from the original features, leaving labels, weights, timestamps and IDs aligned:

    Complete implementation 
    """A project-owned permutation ranker using weighted validation MAE."""

from dataclasses import dataclass, replace

import numpy as np

from ml_toolkit.data import Pool
from ml_toolkit.models import Model


@dataclass(frozen=True)
class PermutationMAERanker:
    """Rank columns by the rise in weighted MAE after one seeded permutation.

    Higher scores identify columns whose disruption hurts predictions more.
    Values may be negative. The model remains fitted; only a copy of one feature
    column changes for each prediction. Targets, weights, timestamps and row
    metadata stay in their original order. No predictions or models are stored.
    """

    seed: int = 42

    def __call__(self, model: Model, data: Pool) -> dict[str, float]:
        """Return one finite importance for every current validation column."""
        target = data.y.to_numpy()
        weights = data.weight.to_numpy()
        baseline = float(
            np.average(np.abs(target - model.predict_pool(data)), weights=weights)
        )
        rng = np.random.default_rng(self.seed)
        importance: dict[str, float] = {}
        for name in data.X.columns:
            shuffled = data.X[name].gather(rng.permutation(len(data)))
            perturbed = replace(data, X=data.X.with_columns(shuffled))
            error = float(
                np.average(
                    np.abs(target - model.predict_pool(perturbed)), weights=weights
                )
            )
            importance[name] = error - baseline
        return importance

    A high score means the fitted model relies on that feature for accurate predictions. Correlated features can share predictive information, and a single permutation is noisy; these scores are not causal effects. The example ranks by MAE even though the workflow reports Poisson deviance.

    from examples.custom_ranker import PermutationMAERanker

ranked = train_model(
    splitter=splitter,
    params=params,
    model_factory=CatBoostLogLinkRegressionModel,
    metric=metrics_frequency,
    run_name="permutation-selection",
    config=config,
    feature_selector=TopKSelector(k=3, ranker=PermutationMAERanker(seed=42)),
)
print("Permutation-selected features:", ranked.features)
assert ranked.test_metrics is not None
print(
    "Test Poisson deviance:",
    round(ranked.test_metrics["mean_poisson_deviance"], 4),
)

    Permutation-selected features: ('temperature', 'feels_like_temperature', 'hour')
Test Poisson deviance: 112.9418

    TopKSelector creates the fitted model supplied to the ranker, applies the returned ordering and evaluates the chosen subset. No model is fitted inside the ranker. Explicit inheritance from FeatureRanker is unnecessary.
