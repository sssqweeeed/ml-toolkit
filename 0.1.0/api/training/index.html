    Training¶

    train_model runs validation, optional feature selection and parameter tuning, then fits a main model and evaluates optional test data. A splitter supplies the rows for each fit.

    Run a holdout experiment¶

    Run this page from an installed repository checkout after python -m examples.prepare_data --dataset bike. The shared examples.training_setup.prepare_training loads all 17,379 original UCI Bike Sharing hours from 2011–2012, with eleven weather/calendar features, rental counts as targets and unit weights. Inputs exclude count components that reveal the target. It configures a local mlflow.db and disables automatic model packaging. The model uses a Poisson loss; predictions are rentals per recorded hour.

    from examples.training_setup import prepare_training
from ml_toolkit import train_model
from ml_toolkit.metrics import metrics_frequency
from ml_toolkit.models import CatBoostLogLinkRegressionModel
from ml_toolkit.training import Holdout

data, params, config = prepare_training()
splitter = Holdout(data, val_size=0.25, test_size=0.2)
result = train_model(
    splitter=splitter,
    params=params,
    model_factory=CatBoostLogLinkRegressionModel,
    metric=metrics_frequency,
    run_name="frequency-holdout",
    config=config,
)
print(
    "Validation Poisson deviance:",
    round(result.validation.mean_metrics["mean_poisson_deviance"], 4),
)
assert result.test_metrics is not None
print(
    "Test Poisson deviance:",
    round(result.test_metrics["mean_poisson_deviance"], 4),
)

    Validation Poisson deviance: 118.8938
Test Poisson deviance: 111.7045

    The latest 20% of rows are test; the last 25% of the remaining rows are validation. This Holdout uses all non-test rows for its test-stage fit. Fractions round upward. The workflow logs metrics and configuration to MLflow.

    Understand the run¶

    1. Consume each validation pair in the splitter's iterator order.
    2. Select columns and tune parameters when those extensions are supplied.
    3. Fit the validation model and run enabled prediction reports and data analysis.
    4. Request splitter.get_test() once and fit a fresh main model on its train, including former validation and gap rows, and evaluate its optional heldout as test. This stage is test when heldout exists, otherwise final_fit.
    5. With fit_on_test=True, request splitter.get_final() after test evaluation and fit a separate model on that full pool, including test.

    The last yielded validation split supplies the final features, parameters, iteration budget and classification threshold. The splitter determines final training rows; they need not match the last validation train. The workflow obtains the main training/test pair after validation; your splitter owns sample separation. Requesting fit_on_test=True without test raises ValueError at that point, before the main fit. Validation fits and their MLflow runs have already completed. Reporting stage flags control additional reports; primary metrics always run.

    Use the result¶

    Result Meaning
    result.model Main adapter fitted on all non-test rows, or all rows when test is absent
    result.final_model Additional model including test when fit_on_test=True, otherwise None
    result.params Last validation split's refit settings, shared by both models
    result.features Selected columns in fitted order
    result.validation.splits Validation results in execution order
    result.validation.mean_metrics Mean validation metrics across splits
    result.test_metrics Independent test metrics from the main model, or None without test
    result.feature_selection, result.tuning Last split's optional search results

    Selection and tuning scores measure the data used to choose settings. The optional test scores describe independent held-out performance. Evaluator and analyzer metrics are logged separately and are not part of these result summaries.

    Optionally train including test¶

    TrainingConfig(fit_on_test=True) adds a fresh fit on all eligible data after independent test evaluation. Both models reuse the last validation split's features, iteration budget, threshold and parameters, without another search. Learned baselines and inflation state are fitted anew for each model.

    Test sample fit_on_test Stages after validation model final_model
    Present False test All non-test rows None
    Present True test, then final_fit All non-test rows All eligible rows
    Absent False final_fit All eligible rows None
    Absent True ValueError after validation, before the main fit — —

    For example, reuse the holdout setup above:

    from dataclasses import replace

full_result = train_model(
    splitter=splitter,
    params=params,
    model_factory=CatBoostLogLinkRegressionModel,
    metric=metrics_frequency,
    run_name="frequency-including-test",
    config=replace(config, fit_on_test=True),
)
assert full_result.final_model is not None

    test_metrics always belongs to the main model and is never replaced with in-sample scores from the additional model. final_fit logs train metrics and applicable train-only custom reports; held-out comparisons are skipped. ReportingConfig.on_test and on_final_fit independently enable additional reports; primary metrics are always calculated.

    TrackingConfig.log_test_model controls test-stage packaging, and log_final_model controls final_fit packaging, including the no-test case. Both default to True. registered_model_name applies to the additional model when requested, otherwise the main model, only if that model's packaging flag is enabled. Disabling its packaging never registers the other model instead.

    Configure the workflow¶

    Pass a model factory, metric and prepared splitter. TrainingConfig controls tuning, shared reporting and packaging. The task recipes show complete combinations.

    Need Guide
    Holdout, time-series CV or custom windows Data splitting
    Select columns or provide a ranker Feature selection
    Supply an Optuna search space or a standalone objective Parameter tuning
    Add prediction reports or custom metrics/artifacts Evaluation
    Analyze feature distributions and drift Data analysis
    Implement a training adapter Models
    Save, reload or inspect MLflow artifacts Tracking

    API reference¶

    Workflow¶

    train_model ¶

    train_model(
    *,
    splitter: Splitter[Pool],
    params: ModelParams,
    model_factory: Callable[[ModelParams], Model],
    metric: Metric,
    run_name: str,
    config: TrainingConfig,
    feature_selector: FeatureSelector | None = None,
    param_space: (
        Callable[[Trial], ModelParams] | None
    ) = None,
    prediction_evaluators: (
        PredictionEvaluator
        | list[PredictionEvaluator]
        | None
    ) = None,
    data_analyzers: (
        DataAnalyzer | list[DataAnalyzer] | None
    ) = None
) -> TrainingResult

    Tune, validate, refit and optionally test a complete training workflow.

    Parameters:

    Name Type Description Default
    splitter Splitter

    Supplies numbered validation pairs and final training/test data. Pools must have aligned features and metadata, ascending timestamps, finite targets and nonnegative weights with positive total. Raw categorical values must not stringify to the reserved "unknown".

    		 required
    params ModelParams

    Base constructor parameters, copied without mutating the input.

    		 required
    model_factory Callable[[ModelParams], Model]

    Creates fresh adapters implementing fit, predict_pool, native_model, best_iteration, feature_importances, get_refit_params and log.

    		 required
    metric Callable

    Receives targets, predictions and weights; returns named scalar scores.

    		 required
    run_name str

    Enclosing MLflow experiment run name.

    		 required
    config TrainingConfig

    Parameter tuning, additional reporting and model packaging settings.

    		 required
    feature_selector FeatureSelector or None

    Selects features independently before tuning on each split. None keeps all columns. The selector owns its settings and must not retain fitted state.

    		 None
    param_space Callable or None

    Optuna trial overrides; required when tuning is enabled.

    		 None
    prediction_evaluators PredictionEvaluator, list[PredictionEvaluator], or None

    Named evaluators called in list order with one combined pool and aligned train and optional val or test labels per fit. Names are unique ignoring case; object IDs are optional. ReportingConfig stage flags gate all reports. None or an empty list disables evaluator calls, not data analysis or PSI/SHAP.

    		 None
    data_analyzers DataAnalyzer, list[DataAnalyzer], or None

    Data reports receiving the same pool and split labels without predictions. Called in list order after prediction evaluators, using the same stage flags and selected features. Names must be unique across both lists and enabled PSI/SHAP. None or [] disables custom data reports, not PSI.

    		 None

    Returns:

    Type Description
    TrainingResult

    Main model, split results, optional test scores and additional final model.
    Notes

    Each split independently selects features using the base parameters, tunes on its validation rows, then fits the winning settings once for reporting. Validation averages are reports, not Optuna objectives. The main model fits splitter.get_test().train using the last split's features and refit parameters. With held-out test data this is the test stage; otherwise it is final_fit. fit_on_test adds a fresh final_fit on splitter.get_final() after test evaluation, without replacing the main model or its scores. No selection or tuning is repeated. MLflow configuration is caller-owned.

    See Also

    ml_toolkit.training.Holdout : A trailing validation window and optional test. ml_toolkit.training.TimeSeriesCV : Chronological validation windows.

    Examples:

    For executable data preparation, configuration, fitting and interpretation of held-out scores, see the documentation's Training guide, "Run a holdout experiment". The Feature selection, Parameter tuning and Evaluation guides show how to extend that workflow with independently prepared examples.

    Per-split selection, tuning and post-tuning evaluation results.

    Final constructor parameters from the last validation split.
    features tuple[str, ...]

    test_metrics dict[str, float] or None

    Main model's independent test scores; None without a test sample.
    final_model Model or None

    Additional model fitted including test only when fit_on_test=True. Never replaces the main model or its test scores.
