    Configuration¶

    TrainingConfig controls tuning, shared reporting, model packaging and optional training including test via fit_on_test=False. Enabling this flag returns an additional result.final_model and requires a held-out test sample. See the training scenarios. A splitter supplies validation and final-fit data. Model factories, metrics, selectors and report objects are explicit train_model arguments.

    Start with a small configuration¶

    from dataclasses import replace
from ml_toolkit.config import ReportingConfig, TrackingConfig, TrainingConfig
from ml_toolkit.evaluation import ObservedFitted, TimeObservedFitted
from ml_toolkit.data_analysis import NumericalFeatureDistributions

config = TrainingConfig(tracking=TrackingConfig(log_test_model=False, log_final_model=False))
with_reports = replace(config, reporting=ReportingConfig(psi=True))
prediction_evaluators = [ObservedFitted(), TimeObservedFitted(period="month")]
data_analyzers = [NumericalFeatureDistributions(period="month")]

    Configurations are immutable keyword-only dataclasses; replace produces a modified copy. Pass evaluator objects separately to select individual reports. Their execution, sample selection and shared feature levels are described in Evaluation and Data analysis. Pass prediction_evaluators= and data_analyzers= separately to train_model. PSI and O/F share ReportingConfig.features and n_bins; each independently fits a LevelTransformer on the same training rows. See how levels are shared.

    Setting Responsibility
    TrainingConfig Tuning, reporting and model packaging settings
    TuningConfig Objective name/direction, trial budget and seed
    ReportingConfig Stage switches, PSI/SHAP and common report options
    FeatureLevelConfig Numerical or categorical feature levels and bounds
    FigureConfig Figure size, resolution and output format
    ShapConfig Explanation sampling and displayed features
    TrackingConfig Which models to package and how to package them

    See Task recipes for complete configuration in a training call, Build an evaluator for custom prediction reports, and Build a data analyzer for custom data reports.

    ReportingConfig dataclass ¶

    ReportingConfig(
    *,
    on_tuning: bool = False,
    on_validation: bool = True,
    on_test: bool = True,
    on_final_fit: bool = True,
    psi: bool = False,
    shap: ShapConfig | None = None,
    features: tuple[FeatureLevelConfig, ...] | None = None,
    n_bins: int = 10,
    epsilon: float = 1e-06,
    period: TimePeriod = "month",
    figure: FigureConfig = FigureConfig()
)

    Enable reporting by training stage and configure PSI, SHAP and exports.

    Stage switches gate prediction evaluators, data analyzers, PSI and SHAP, including their additional metrics and report artifacts, not training metrics or optimization. PSI baseline packaging follows model logging flags independently of stage report switches. All validation folds use the same settings. PSI and observed/fitted use feature levels fitted on training rows. features=None infers all input features; () disables level reports. period and epsilon apply only to PSI.

    Parameters:

    Name Type Description Default
    on_tuning bool

    Enable additional reports for Optuna trials.

    		 False
    on_validation bool

    Enable additional reports for every completed validation fold.

    		 True
    on_test bool

    Enable additional reports for the model evaluated on held-out test data.

    		 True
    on_final_fit bool

    Enable applicable train-only reports after fitting all eligible data.

    		 True
    psi bool

    Enable population stability reports and baseline packaging with saved models; uses no predictions. features=() disables the baseline too.

    		 False
    shap ShapConfig or None

    Optional native-model explanations of held-out rows.

    		 None
    features tuple[FeatureLevelConfig, ...] or None

    Shared feature definitions; None infers columns, () disables levels.

    		 None
    n_bins int

    Positive number of train-fitted numerical quantile bins.

    		 10
    epsilon float

    PSI share floor strictly between zero and one.

    		 1e-6
    period TimePeriod

    Calendar period for temporal PSI distributions.

    		 "month"
    figure FigureConfig

    Shared image dimensions, resolution and output format.

    		 FigureConfig()

    FeatureLevelConfig dataclass ¶

    FeatureLevelConfig(
    name: str,
    ftype: FeatureType,
    error_level: FeatureScalar | None = None,
    null_level: FeatureScalar | None = None,
    lower_bound: float | None = None,
    upper_bound: float | None = None,
)

    Configure how one feature is assigned to diagnostic levels.

    Parameters:

    Name Type Description Default
    name str

    Nonempty feature column name.

    		 required
    ftype ('categorical', 'numerical')

    Choose category levels or reference quantile intervals.

    		 'categorical'
    error_level FeatureScalar or None

    Optional sentinel mapped to ERROR; must differ from null_level and must not be NaN.

    		 None
    null_level FeatureScalar or None

    Optional sentinel treated as missing alongside actual nulls and floating NaNs.

    		 None
    lower_bound float or None

    Inclusive numerical lower bound; values below it map to ERROR. None leaves the lower tail unbounded.

    		 None
    upper_bound float or None

    Inclusive numerical upper bound; values above it map to ERROR. None leaves the upper tail unbounded.

    		 None
    Notes

    Bounds apply only to numerical features. Regular categories must not use reserved diagnostic level strings.

    Examples:

    Fit age intervals once, then keep invalid and missing values separate.

    >>> import polars as pl
>>> from ml_toolkit.feature_levels import FeatureLevelConfig, LevelTransformer
>>> feature = FeatureLevelConfig("age", "numerical", lower_bound=0)
>>> levels = LevelTransformer((feature,), n_bins=2).fit(
...     pl.DataFrame({"age": [20, 30, 40, 50]})
... )
>>> current = pl.DataFrame({"age": [-1, None, 25, 45]})
>>> levels.transform(current)["age"].cast(pl.String).to_list()
['__ERROR__', '__NULL__', '[0, 35)', '[35, inf)']

    TrackingConfig dataclass ¶

    TrackingConfig(
    *,
    log_trial_models: bool = False,
    log_validation_models: bool = False,
    log_test_model: bool = True,
    log_final_model: bool = True,
    input_example_rows: int = 5,
    model_name: str = "model",
    registered_model_name: str | None = None,
    conda_env: Path | None = None
)

    Configure model packaging in an externally configured MLflow store.

    Parameters:

    Name Type Description Default
    log_trial_models bool

    Package each trial model in each split's Optuna study.

    		 False
    log_validation_models bool

    Package each split's post-tuning validation model.

    		 False
    log_test_model bool

    Package the model fitted without test and evaluated on held-out test rows.

    		 True
    log_final_model bool

    Package a model fitted on all eligible rows, including when no test exists.

    		 True
    input_example_rows int

    Positive maximum serving-example row count, capped at sample size.

    		 5
    model_name str

    Nonempty MLflow model artifact name shared across nested runs.

    		 'model'
    registered_model_name str or None

    Registry name for the additional model when fit_on_test is enabled, otherwise for the main model. Requires that model's logging flag.

    		 None
    conda_env Path or None

    Existing serving environment file; None pins installed dependencies.

    		 None
    Notes

    Metrics, run metadata, and configuration artifacts are always logged. The caller owns tracking URI, experiment selection, and Python logging.

    TimePeriod supports minute, hour, day, week, month, quarter and year. Temporal reports preserve input timezones. Standalone PSI also accepts these settings through its own API.
