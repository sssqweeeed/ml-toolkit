    Data¶

    Pool is the toolkit's ready-to-use data container for aligned Polars features, targets, dates, weights, and row metadata. Instantiate it with your prepared data; row operations and backend conversions are included in the package.

    Prepare a pool¶

    After installing the package, create a pool directly. This small constructed fixture demonstrates container operations; it is not an evaluation dataset:

    from datetime import date, timedelta

import polars as pl

from ml_toolkit.data import Pool

n_rows = 24
frame = pl.DataFrame(
    {
        "age": [20 + i % 10 for i in range(n_rows)],
        "region": ["north", "south"] * (n_rows // 2),
        "target": [float(i % 3) for i in range(n_rows)],
        "date": [date(2025, 1, 1) + timedelta(days=i) for i in range(n_rows)],
        "weight": [1.0] * n_rows,
    }
).sort("date")
data = Pool(
    X=frame.select("age", "region"),
    y=frame["target"],
    time=frame["date"],
    weight=frame["weight"],
    cat_features=("region",),
    numerical_features=("age",),
)

    There are 24 rows and two model features. Targets, timestamps, weights, IDs, and reporting groups stay outside X unless they are model features.

    Slice without losing alignment¶

    first_week = data.take(range(7))
age_only = first_week.select_features(["age"])

print("Selected rows and features:", len(age_only), age_only.X.columns)
reordered = data.take([2, 0, 2])
print("Aligned (age, target, date):")
for age, target, time in zip(reordered.X["age"], reordered.y, reordered.time):
    print(age, target, time)
print("Original rows:", len(data))

    Selected rows and features: 7 ['age']
Aligned (age, target, date):
22 2.0 2025-01-03
20 0.0 2025-01-01
22 2.0 2025-01-03
Original rows: 24

    The selection repeats row 2 around row 0; their ages, targets, and dates move together. Weights and optional IDs and reporting groups follow the same order. Feature selection filters feature declarations as well as X. Both operations return new containers, leaving the original 24 rows intact. Reordered data is useful for inspection; training still requires ascending timestamps.

    Contiguous nonnegative row selections, including ranges and arrays of consecutive indices, share the source buffers. Reordered, repeated or noncontiguous positions allocate gathered rows. Feature selection also shares column buffers. A small slice can therefore keep its larger source allocation alive.

    Replace a target without changing rows¶

    For example, prepare a log-transformed target while keeping original counts available for comparison:

    transformed = data.with_target(data.y.cast(pl.Float64).log1p())
print("Original targets:", data.y.head(3).to_list())
print("Log1p targets:", transformed.y.head(3).round(4).to_list())
print("Dates preserved:", transformed.time.equals(data.time))

    Original targets: [0.0, 1.0, 2.0]
Log1p targets: [0.0, 0.6931, 1.0986]
Dates preserved: True

    A model fitted to this transformed target predicts on the transformed scale; convert predictions back before comparing them with original counts. The original pool remains available with unchanged targets.

    Convert features and baseline for a backend¶

    This conversion example includes a missing category. Use a small copy of the prepared pool so the shared data keeps its original values:

    from dataclasses import replace

with_missing = replace(
    data.take([0, 1, 2]),
    X=data.X.head(3).with_columns(
        pl.Series("region", ["north", None, "south"])
    ),
)
model_input = with_missing.to_model_input()
print("Backend categories:", model_input["region"].tolist())
print("Source categories:", with_missing.X["region"].to_list())
native = with_missing.to_catboost(baseline=0.25)
print("Backend features:", native.get_feature_names())
print("Raw-score baseline:", native.get_baseline().reshape(-1).tolist())

    Backend categories: ['north', 'unknown', 'south']
Source categories: ['north', None, 'south']
Backend features: ['age', 'region']
Raw-score baseline: [0.25, 0.25, 0.25]

    to_model_input() returns pandas feature columns with dictionary-encoded categories whose labels are strings, and fills missing categories with "unknown". For MLflow serving or serialization, use to_model_input(categorical_as_strings=True) to expand categories to strings. to_catboost() also carries targets, weights, and timestamps, broadcasting a scalar baseline to every row. The baseline is a raw model score, not a prediction on the response scale; a log-link model interprets 0.25 on the log scale.

    Training reserves the literal category "unknown" for missing values. Raw categorical columns in training and validation inputs must not already contain that value after string conversion, even when they have no missing values. Training reports the offending column. Prepared model inputs, prediction and serving continue to accept "unknown"; ordinary missing values are still filled.

    Use the shared container¶

    The same class is available from ml_toolkit and ml_toolkit.data for construction and type annotations:

    from ml_toolkit import Pool

    Row fields¶

    Fields Contract
    X, y, time, weight Aligned, nonempty Polars frame/series; one value per row
    cat_features, numerical_features Tuples of feature names present in X
    object_id Aligned string/integer IDs or None; optional for evaluators that join external data
    business_type Aligned diagnostic groups or None

    Training validates ascending non-null Date/Datetime timestamps, finite targets, and finite nonnegative weights with a positive total. Optional metadata defaults to None. Fields cannot be reassigned; contained frames and series are not deeply immutable.

    Row and feature operations¶

    take preserves requested row order, including repeated indices. select_features preserves all row metadata and filters feature declarations. with_target preserves rows and their metadata. Each method returns the same concrete container type, so chronological splitting and selection retain your container type.

    Backend conversion¶

    The bundled CatBoost adapters call to_catboost for fitting and to_model_input for named feature frames and serving examples. Preserve fitted feature names and categorical handling in both conversions. A scalar baseline must be broadcast across rows; array baselines must stay aligned.

    Array types¶

    Import FloatArray and IntArray from ml_toolkit.types when annotating your functions. They mean NumPy float64 and int64 arrays; individual APIs describe the required shape. ModelParams is the backend parameter dictionary.

    API reference¶

    Data container¶

    Pool dataclass ¶

    Pool(
    X: DataFrame,
    y: Series,
    time: Series,
    weight: Series,
    business_type: Series | None = None,
    cat_features: tuple[str, ...] = (),
    numerical_features: tuple[str, ...] = (),
    *,
    object_id: Series | None = None
)

    Hold aligned features, targets, timestamps, weights, and row metadata.

    Projects prepare the data and may optionally supply business_type for grouped plots. Feature lists may describe only a subset of X's columns. Fields cannot be reassigned; the contained frames and series are not deeply immutable. Pool methods return new objects without modifying their inputs.

    Construction checks alignment, timestamp dtype, and feature metadata. Training additionally validates chronological order, finite targets, and finite, nonnegative weights with positive total.

    Parameters:

    Name Type Description Default
    X DataFrame

    Feature columns, with one row per observation.

    		 required
    y Series

    Target values aligned with X.

    		 required
    time Series

    Date or Datetime values aligned with X.

    		 required
    weight Series

    Row weights aligned with X.

    		 required
    business_type Series or None

    Optional aligned groups for diagnostic plots.

    		 None
    cat_features tuple[str, ...]

    Names of categorical features in X.

    		 ()
    numerical_features tuple[str, ...]

    Names of numerical features in X.

    		 ()
    object_id Series or None

    Optional non-null string or integer IDs aligned with X. Keyword-only; repeated IDs are allowed. IDs retain their dtype and values through row and feature operations and are not added to model inputs.

    		 None

    Backend conversion¶

    to_model_input ¶

    to_model_input(
    n_rows: int | None = None,
    *,
    categorical_as_strings: bool = False
) -> pd.DataFrame

    Return all or the first n_rows as a categorical-safe pandas frame.

    Oversized limits return all rows. Null categorical values become "unknown". Categorical columns retain dictionary encoding with string labels. Row order is preserved so inputs stay aligned with metadata.

    Parameters:

    Name Type Description Default
    n_rows int or None

    Nonnegative row limit; None includes all rows.

    		 None
    categorical_as_strings bool

    Expand categorical columns to strings for serialization or MLflow serving signatures. Model training and prediction accept the default pandas categorical columns without this expansion.

    		 False

    Returns:

    Type Description
    DataFrame

    Feature columns in their existing order, without row metadata.

    Raises:

    Type Description
    ValueError

    n_rows is negative.
