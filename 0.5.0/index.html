    ml-toolkit¶

    Prepare data, choose a model and metric, then train, evaluate and record an experiment with the same workflow across tasks. Splitter and evaluator objects control data partitions and additional reports.

    Start here¶

    • Getting started: installation and one complete training run.
    • Task recipes: model, metric and report choices for your target.
    • Data: prepare a Pool and preserve row alignment when slicing.
    • Training: run the workflow and interpret its result.
    • Models: fit, predict, save and load a supported adapter.

    Follow the workflow¶

    1. A splitter supplies train/validation pairs.
    2. Each pair independently selects features, tunes parameters and fits a model. Selection and tuning are optional.
    3. A fresh main model uses the last pair's selected settings and splitter.get_test().train, including former validation and gap rows.
    4. With test data, the test stage evaluates the held-out pool. Without test, this fit is named final_fit and uses all eligible rows.
    5. With fit_on_test=True, a separate final_fit includes test and returns result.final_model. Without test, requesting this option is an error. Metrics, reports and model artifacts are recorded in MLflow.

    Built-in splitters reserve chronological windows and refit on all non-test rows. Custom splitters define their own windows and final training data. The caller prepares features and targets and selects the MLflow experiment.
