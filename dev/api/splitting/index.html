    Data splitting¶

    Bind a prepared Pool to a splitter, then pass that object to train_model. The same object also supplies pairs for direct fitting outside the workflow.

    Choose a strategy¶

    Strategy Validation Main training
    Holdout One trailing validation sample All rows before optional test
    TimeSeriesCV Expanding or bounded chronological windows All rows before optional test
    Custom Splitter Pairs yielded by your implementation Exactly get_test().train

    Input pools require ascending timestamps and aligned finite targets and weights, with nonnegative weights and positive total weight. Splits preserve metadata, row order and the concrete pool type. See Data for preparing a pool.

    Inspect chronological windows¶

    Run from an installed checkout after python -m examples.prepare_data --dataset bike. The imported prepare_training() loads the original Bike Sharing hours, model parameters and local MLflow settings described in the training example. Targets are rentals per hour; weights are one per recorded hour.

    from examples.training_setup import prepare_training
from ml_toolkit import train_model
from ml_toolkit.metrics import metrics_frequency
from ml_toolkit.models import CatBoostLogLinkRegressionModel
from ml_toolkit.training import Holdout

data, params, config = prepare_training()
splitter = Holdout(data, val_size=0.25, test_size=0.2)

    import pandas as pd
from ml_toolkit.data import Pool
from ml_toolkit.training import Splitter, TimeSeriesCV


def split_table(strategy: Splitter[Pool]) -> pd.DataFrame:
    rows = []
    for part in strategy.get_validation():
        assert part.heldout is not None
        for sample, pool in (("train", part.train), ("val", part.heldout)):
            rows.append(
                (
                    str(part.index),
                    sample,
                    len(pool),
                    str(pool.time[0])[:10],
                    str(pool.time[-1])[:10],
                )
            )
    final = strategy.get_test()
    for sample, pool in (("train", final.train), ("test", final.heldout)):
        if pool is not None:
            rows.append(
                (
                    "final",
                    sample,
                    len(pool),
                    str(pool.time[0])[:10],
                    str(pool.time[-1])[:10],
                )
            )
    return pd.DataFrame(
        rows, columns=["fold", "sample", "rows", "first date", "last date"]
    )


print("Holdout")
print(split_table(splitter).to_string(index=False))
cv = TimeSeriesCV(data, n_splits=3, test_size=0.2, gap=24)
print("\nTimeSeriesCV")
print(split_table(cv).to_string(index=False))

    The tables show calendar dates for compact display. Counts use the exact hourly observations; adjacent samples can begin and end on the same date without sharing rows.

    Each CV fold leaves 24 recorded rows between training and validation. They are included again in the main train. Rows need not be equally spaced in clock time: integer gap, integer sizes and max_train_size count observations.

    test_size accepts a row count, fraction of the original pool, calendar date, YYYY-MM-DD string, or None. Dates start test inclusively in the data's timezone; when a date has no observations, the next observation starts test. Datetimes are not accepted. Fractions round upward, and both resulting samples must be nonempty. Validation fractions use only the retained non-test rows.

    TimeSeriesCV.val_size=None divides the retained rows into equal validation blocks. max_train_size limits each CV training window, but not final training; skip_splits omits initial folds and preserves their original one-based indices. Without test, built-in final training uses the entire pool.

    Use a duration gap¶

    Pass datetime.timedelta directly; no conversion to milliseconds is needed.

    from datetime import timedelta

duration_cv = TimeSeriesCV(data, n_splits=3, test_size=0.2, gap=timedelta(days=1))
for part in duration_cv.get_validation():
    assert part.heldout is not None
    assert part.train.time[-1] <= part.heldout.time[0] - timedelta(days=1)

    gap=timedelta(seconds=1) is also supported. Preceding rows are retained when time <= validation_start - gap, including equality. Zero duration matches zero row gap. The duration measures elapsed time across timezone/DST changes; Date values represent midnight and sub-day gaps are not rounded. A duration of 30 days is exactly 30 days, not a calendar month.

    Validation windows and the test boundary stay unchanged. CV applies max_train_size after excluding the gap. Negative gaps or an empty train in a used fold raise ValueError. Gap rows remain available for later fitting. parameters() stores row gaps as integers and durations as {"type": "timedelta", "microseconds": N}.

    Fit outside the workflow¶

    Continue with splitter, params and the model imported above:

    part = next(splitter.get_validation())
assert part.heldout is not None
model = CatBoostLogLinkRegressionModel(params).fit(part.train, part.heldout)
final = splitter.get_test()
final_model = CatBoostLogLinkRegressionModel(model.get_refit_params()).fit(
    final.train
)
assert final.heldout is not None
prediction = final_model.predict_pool(final.heldout)
print("Final test predictions:", prediction.shape)

    Final test predictions: (3476,)

    Each get_validation() call creates a fresh iterator. Direct use leaves iteration, metrics and logging to the caller. train_model consumes one pair at a time and calls get_test() once after validation, so test pools are not retained during validation. With fit_on_test=True, it calls get_final() after test evaluation for an additional full-data fit.

    Implement a splitter¶

    Subclass Splitter and implement two methods. get_validation() yields Split(train, heldout, index) with a nonempty validation heldout and positive, unique indices. Iterator order determines execution order. At least one pair is required. get_test() returns Split(train, heldout) where heldout is optional test; its index is ignored. Its train contains every eligible non-test row, or the entire eligible pool when test is absent. The separate get_final() method defaults to self.data; override it to customize the full pool used for additional training including test. It returns a pool, not a Split.

    This reusable example uses explicit positional boundaries:

    Complete implementation 
    """Project-defined row boundaries for validation and final fitting."""

from collections.abc import Iterator

from ml_toolkit.data import Pool
from ml_toolkit.training import Split, Splitter


class ProjectSplitter(Splitter[Pool]):
    def __init__(self, data: Pool, *, validation_start: int, test_start: int):
        super().__init__(data)
        if not 0 < validation_start < test_start < len(data):
            raise ValueError(
                "Boundaries must leave nonempty train, validation and test"
            )
        self.validation_start = validation_start
        self.test_start = test_start

    def get_validation(self) -> Iterator[Split[Pool]]:
        yield Split(
            self.data.take(range(self.validation_start)),
            self.data.take(range(self.validation_start, self.test_start)),
            index=1,
        )

    def get_test(self) -> Split[Pool]:
        return Split(
            self.data.take(range(self.test_start)),
            self.data.take(range(self.test_start, len(self.data))),
        )

    def parameters(self) -> dict[str, object]:
        return {
            "validation_start": self.validation_start,
            "test_start": self.test_start,
        }

    Use it in the ordinary workflow:

    from examples.custom_splitter import ProjectSplitter

project_splitter = ProjectSplitter(
    data, validation_start=len(data) // 2, test_start=3 * len(data) // 4
)
project_result = train_model(
    splitter=project_splitter,
    params=params,
    model_factory=CatBoostLogLinkRegressionModel,
    metric=metrics_frequency,
    run_name="project-splits",
    config=config,
)
print("ProjectSplitter")
print(split_table(project_splitter).to_string(index=False))
print("Validation folds fitted:", len(project_result.validation.splits))

    Keep the original pool in self.data; generate a fresh iterator on each call. The workflow checks valid pools, matching feature schemas and declarations within each pair, and selected-feature availability in final data. Your splitter owns sample membership and leakage prevention. IDs are optional and may repeat; no ID-based overlap check is performed. Preserve row metadata by using Pool.take.

    parameters() defaults to {}. Override it with explicit JSON-compatible settings to log them alongside the class name in configuration/splitter.json. Do not return data, generators or fitted models. The splitter supplies data; model fitting, refitting and serving belong to the model adapter.
