    PSI and feature levels¶

    Part of Data analysis, Population Stability Index (PSI) measures how feature distributions change between a reference sample and a current sample. Fit categories and numerical bins on the reference once, then reuse them for every comparison.

    Compare two samples¶

    This small calculation makes the level counts easy to inspect; four rows per sample are not enough to establish population drift. For monitoring real observations, see the recorded-hour comparison.

    import polars as pl

from ml_toolkit.config import FeatureLevelConfig
from ml_toolkit.psi import PSIAnalysis, PSIConfig

reference = pl.DataFrame(
    {"age": [20, 30, 40, 50], "region": ["north", "north", "south", "south"]}
)
current = pl.DataFrame(
    {"age": [45, 55, 65, 75], "region": ["north", "south", "west", "west"]}
)
analysis = PSIAnalysis(
    PSIConfig(
        features=(
            FeatureLevelConfig("age", "numerical", lower_bound=0),
            FeatureLevelConfig("region", "categorical"),
        ),
        n_bins=2,
    )
).fit(reference)
comparison = analysis.compare(current)
print(
    comparison.psi.sort("feature")
    .with_columns(pl.col("psi").round(4))
    .write_csv(),
    end="",
)
region_shares = (
    comparison.level_distribution.filter(
        (pl.col("feature") == "region") & (pl.col("level") != "__NULL__")
    )
    .select("level", "sample", "share")
    .pivot(on="sample", index="level", values="share")
)
print(region_shares.write_csv(), end="")

    feature,psi
age,6.9077
region,6.9077
level,reference,current
north,0.5,0.25
south,0.5,0.25
__UNSEEN__,0.0,0.5

    comparison.psi has one score per feature. Larger values mean a greater change in fitted-level shares. level_distribution shows the reference/current counts and shares behind each score. The new "west" category uses the fitted unseen level; numerical bins retain the reference boundaries. Here north and south each fall from 50% to 25%, and unseen categories account for 50% of current rows. Empty levels make the score sensitive to the configured epsilon share floor; this value is an arithmetic demonstration, not a universal alert threshold.

    Call analysis.compare(next_sample) for later batches. Re-fitting on each batch would change the reference. For temporal distributions, set PSIConfig(period="week") (default "month") and provide aligned Date/Datetime timestamps with time= in both fit and compare. The original ranges must satisfy max(reference_time) <= min(current_time). Equal endpoints are allowed; overlap beyond the shared endpoint and reversed ranges raise ValueError. The split may fall inside one grouping period. Comparisons without timestamps do not have this restriction.

    Reuse feature levels¶

    LevelTransformer exposes the same fit/transform operations when you need consistent bins for another report. Continue with reference and current above to transform both samples and compare their existing levels:

    FeatureLevelConfig supplies the rules for each column. fit(reference) determines categories or numerical intervals from the reference sample; it does not train a prediction model. The resulting feature_levels tuple contains one FeatureLevels per configured column, in the same order. Each result holds its original rules in config, its labels in levels, and its numerical boundaries or categorical categories.

    from ml_toolkit.feature_levels import LevelTransformer
from ml_toolkit.psi import compare_psi

levels = LevelTransformer(analysis.config.features, n_bins=2).fit(reference)
reference_levels = levels.transform(reference)
current_levels = levels.transform(current)
assert levels.feature_levels is not None
level_comparison = compare_psi(
    reference_levels, current_levels, feature_levels=levels.feature_levels
)
print("Age boundaries:", levels.feature_levels[0].boundaries)
print(
    "Current region levels:", current_levels["region"].cast(pl.String).to_list()
)
print("Same PSI scores:", level_comparison.psi.equals(comparison.psi))

    Age boundaries: (35.0,)
Current region levels: ['north', 'south', '__UNSEEN__', '__UNSEEN__']
Same PSI scores: True

    Configured columns become Polars Categorical columns; other columns retain their values and order. Reuse the fitted transformer for subsequent samples. Calling fit again replaces its levels; previously returned comparison results retain their original immutable rules and levels.

    How PSI and observed/fitted share levels¶

    During training, PSI and ObservedFitted receive the same ReportingConfig.features rules and ReportingConfig.n_bins. Each report uses levels fitted on the same training rows for that fit. PSI reuses the fitted transformer from the model's baseline when that model is being saved; ObservedFitted creates its own transformer. PSI and observed/fitted do not share a fitted transformer with each other.

    The same rules, bin count and reference data produce identical categories and numerical boundaries for matching features. Identical configuration alone is insufficient when the reference data differs. ObservedFitted(features=...) can select a subset of the shared feature definitions without changing how those features are binned.

    Each report applies its training-fitted levels to both train and validation/test rows. Held-out rows do not influence the learned levels. Every enabled fit learns levels afresh from its own training rows, so boundaries can differ across folds and the final fit. See the observed/fitted guide for the corresponding prediction report.

    Compare recorded weather and calendar features¶

    Prepare the Bike Sharing cache. These figures fit levels on 2011 training hours and compare 2012 test hours. Calendar changes can be expected; PSI measures distribution differences, not their cause. Shares count rows, independent of model weights.

    from pathlib import Path

import polars as pl

from examples.gallery_data import load_bike_pool
from ml_toolkit.training import Holdout
from ml_toolkit.config import FigureConfig

data = load_bike_pool(download_if_missing=False)
partition = Holdout(data, test_size="2012-01-01").get_test()
train, test = partition.train, partition.heldout
assert test is not None
output = Path("figures")
figure = FigureConfig(dpi=150)
print(f"2011 train hours: {len(train)}; 2012 test hours: {len(test)}")

    2011 train hours: 8645; 2012 test hours: 8734

    from ml_toolkit.plots import psi

categorical_features = {
    "hour",
    "working_day",
    "weekday",
    "holiday",
    "season",
    "weather",
    "month",
}
weather_analysis = PSIAnalysis(
    PSIConfig(
        features=tuple(
            FeatureLevelConfig(
                name,
                "categorical" if name in categorical_features else "numerical",
            )
            for name in train.X.columns
        ),
        n_bins=10,
    )
).fit(train.X, time=train.time)
weather_comparison = weather_analysis.compare(test.X, time=test.time)
psi.feature_psi_plot(
    weather_comparison.psi, output / "psi-scores.png", figure=figure
)
print(
    weather_comparison.psi.sort("psi", descending=True)
    .head(5)
    .with_columns(pl.col("psi").round(3))
    .write_csv(),
    end="",
)

    feature,psi
humidity,0.048
temperature,0.036
feels_like_temperature,0.033
weather,0.004
wind_speed,0.004

    The bars show one PSI score per feature. Inspect its level shares to understand which values contribute to the difference; a universal alert cutoff is not implied by this illustration.

    psi.time_psi_level_distribution(
    weather_comparison.time_distribution,
    "temperature",
    output / "psi-time.png",
    figure=figure,
)

    Each bar shows period-specific shares on the fitted levels. The dashed boundary marks the first current bar. When the split falls inside a period, that period has two equal-width bars, reference then current; the separator marks their visual boundary, not the exact split date. Entirely missing periods stay empty. Both plotting calls return None; their tables come from PSIAnalysis.

    Enable PSI during training¶

    from ml_toolkit.config import ReportingConfig

reporting = ReportingConfig(
    psi=True, features=weather_analysis.config.features, n_bins=10
)

    Pass this reporting config to TrainingConfig(reporting=reporting). The workflow compares train with the current held-out sample, writes psi/scores.png and per-feature time distributions, and saves the score and distribution tables as JSON. PSI uses feature values and timestamps only; no predictions are passed to the analysis. A train-only fit has no PSI report. features=None infers feature rules; features=() disables feature diagnostics. epsilon is the PSI share floor, and period sets temporal grouping. Scheduling and shared figure settings are described in the data analysis overview.

    Persist a reference for monitoring¶

    PSIBaseline stores fitted feature rules and aggregate counts rather than retaining a row-level reference frame. Continue with the small reference and current samples above to save and reload it locally without MLflow:

    from tempfile import TemporaryDirectory
from polars.testing import assert_frame_equal
from ml_toolkit.psi import PSIBaseline

baseline = PSIBaseline.from_reference(
    reference, config=analysis.config
)
with TemporaryDirectory() as directory:
    baseline.save(directory)
    restored = PSIBaseline.load(directory)

result = restored.compare(current)
assert_frame_equal(result.psi, comparison.psi)
assert_frame_equal(result.level_distribution, comparison.level_distribution)

    Numerical boundaries, typed categories, missing/error sentinels and feature order survive serialization. LevelTransformer.to_dict() and from_dict() also expose the fitted transformation state separately. Loading does not refit any levels.

    compare returns the existing PSIResult with feature scores and reference/current distributions. Counts are unweighted, and epsilon floors shares independently without renormalization, exactly as in PSIAnalysis. The batch must be nonempty and contain all configured features; extra columns are allowed.

    time= in from_reference records the reference date range as metadata. The baseline's time_distribution is empty: compare each incoming monitoring window separately against the same fixed reference. Existing temporal reports in PSIAnalysis and training remain available.

    During training, enabled PSI is bundled automatically with saved models. See loading a model's baseline.

    Discrete-series comparison¶

    psi ¶

    psi(
    reference: Series,
    current: Series,
    *,
    epsilon: float = 1e-06
) -> float

    Calculate PSI for two categorical feature distributions.

    Parameters:

    Name Type Description Default
    reference Series

    Nonempty Series of discrete reference levels, compared after casting to String. Bin continuous numerical values before calling.

    		 required
    current Series

    Nonempty Series of discrete current levels, compared after casting to String; sample sizes may differ. Null is counted as a separate level.

    		 required
    epsilon float

    Minimum share strictly between zero and one used to avoid logarithms of zero.

    		 1e-6

    Returns:

    Type Description
    float

    Sum of (current_share - reference_share) * log(current_share / reference_share) over the union of observed levels.

    Raises:

    Type Description
    ValueError

    Either sample is empty or epsilon is invalid.
    Notes

    Shares are floored independently without renormalization. Use LevelTransformer or PSIAnalysis to bin raw numerical values first.

    Examples:

    Compare category shares: north falls from 75% to 25%, while south rises.

    >>> import polars as pl
>>> from ml_toolkit.psi import psi
>>> reference = pl.Series(["north"] * 3 + ["south"], dtype=pl.Categorical)
>>> current = pl.Series(["north"] + ["south"] * 3, dtype=pl.Categorical)
>>> round(psi(reference, current), 4)
1.0986

    Level definitions¶

    FeatureLevels dataclass ¶

    FeatureLevels(
    config: FeatureLevelConfig,
    levels: tuple[str, ...],
    boundaries: tuple[float, ...] = (),

)

    Store categories and intervals determined from reference data.

    Attributes:

    Name Type Description
    config FeatureLevelConfig
