    Tracking¶

    train_model records its experiment in MLflow. Set the tracking URI and experiment before calling it; the toolkit uses the active run as a parent when one already exists. The same table helpers also work outside training.

    Inspect a training run¶

    A workflow has a parent named by run_name, a validation run containing validation/split_<index> runs, and a test run when test exists. Without test, the main fit is final_fit; with test and fit_on_test=True, a separate final_fit follows test evaluation. Selection history is stored in selection/history.json inside each split; tuning uses nested tuning and trial_<number> runs. The final fit uses the last yielded split's settings and the final data supplied by the splitter.

    Where to look Contents
    Parent configuration/requested.json Shared training configuration
    Parent configuration/splitter.json Splitter class and explicit parameters
    Parent configuration/evaluators.json Prediction evaluator classes, names and parameters
    Parent configuration/data_analyzers.json Data analyzer classes, names and parameters
    Parent configuration/resolved.json Final selected features and model settings
    validation Averages of primary validation metrics
    validation/split_<index> Train/validation metrics, optional selection, trials and reports
    test Main model train/test metrics, reports and optional model
    final_fit All-data train metrics, applicable reports and optional model; no independent test metrics

    Primary metrics drive training and tuning; evaluator and analyzer metrics are additional named measurements. See Evaluation and Data analysis for report scheduling, metric names and artifact paths. The complete task recipe shows selection, tuning, SHAP and final model packaging together.

    TrackingConfig controls packaging for trials, validation, test and final fitting. log_test_model=True saves the test-stage main model; log_final_model=True saves the final-fit model, including when test is absent. Registration selects the additional model when trained, otherwise the main model, and requires that model's logging flag. It never falls back to the other model. Each stage logs its own row counts and timestamp ranges. Model methods preserve their prediction transformation when saving and loading; use the model serving guide or the custom adapter guide for that contract.

    Prepare a fitted model¶

    This independent example uses recorded Bike Sharing hours. The last 20% are held out; the preceding data contains a trailing 25% validation window. Run python -m examples.prepare_data --dataset bike from the checkout once.

    import numpy as np
from examples.gallery_data import load_bike_pool
from ml_toolkit.models import CatBoostRegressionModel
from ml_toolkit.training import Holdout

data = load_bike_pool(download_if_missing=False)
splitter = Holdout(data, val_size=0.25, test_size=0.2)
part = next(splitter.get_validation())
test = splitter.get_test().heldout
assert test is not None
model = CatBoostRegressionModel(
    {
        "iterations": 40,
        "depth": 4,
        "loss_function": "RMSE",
        "random_seed": 42,
        "thread_count": 2,
        "verbose": False,
        "allow_writing_files": False,
    }
).fit(part.train, part.heldout)

    Save a table in MLflow¶

    import mlflow
import polars as pl

from ml_toolkit.tracking import log_polars_table

mlflow.set_tracking_uri("sqlite:///mlflow.db")
mlflow.set_experiment("ml-toolkit-examples")
predictions = model.predict_pool(test)
table = (
    test.X.select("working_day")
    .with_columns(
        pl.Series("absolute_error", np.abs(test.y.to_numpy() - predictions))
    )
    .group_by("working_day")
    .agg(
        pl.col("absolute_error").mean().round(3).alias("mae"),
        pl.len().alias("hours"),
    )
    .sort("working_day")
)
with mlflow.start_run(run_name="segment-metrics") as run:
    log_polars_table(table, "tables/segment-metrics.json")
    saved = mlflow.artifacts.load_dict(
        f"runs:/{run.info.run_id}/tables/segment-metrics.json"
    )
    print(saved)

    {'rows': [{'working_day': 0, 'mae': 89.048, 'hours': 1127}, {'working_day': 1, 'mae': 101.836, 'hours': 2349}]}

    The table summarizes held-out absolute error in rentals per hour by the recorded working-day flag, alongside the number of hours in each group. The call creates a local MLflow database if needed and writes a JSON artifact containing the table's rows under the active run. The example reads back the saved payload to verify its contents. Model adapters expose their own model-packaging methods in the model reference.

    API reference¶

    load_psi_baseline ¶

    load_psi_baseline(model_uri: str) -> PSIBaseline

    Load the named PSI artifact from a model URI or local model directory.

    Accepts MLflow model IDs, registered versions and run model URIs. Prefer immutable versions when loading predictions and monitoring separately. Does not import or instantiate the predictive model. Missing baselines raise FileNotFoundError; malformed or unsupported state raises ValueError.

    log_polars_table ¶

    log_polars_table(
    table: DataFrame, artifact_file: str
) -> None

    Log Polars records as a JSON artifact without converting to pandas.

    Parameters:

    Name Type Description Default
    table DataFrame

    Table whose rows can be serialized by MLflow.

    		 required
    artifact_file str

    Artifact-relative JSON file path in the MLflow run.

    		 required
    Notes

    Calls mlflow.log_dict with a {"rows": table.to_dicts()} payload. Uses the active run, or MLflow's implicit run if no run is active.

    Load a model's PSI baseline¶

    With ReportingConfig(psi=True), each saved model includes a psi_baseline artifact containing fitted feature levels and unweighted reference counts. The existing TrackingConfig.log_trial_models, log_validation_models, log_test_model, and log_final_model switches control this packaging; no additional tracking switch is needed. ReportingConfig.on_* controls reports, so disabling a stage's reports does not remove the saved model's baseline. features=() explicitly disables both levels and their baseline.

    The training workflow prepares this artifact automatically. For the model fitted above outside the workflow, attach it explicitly when logging:

    from tempfile import TemporaryDirectory
from ml_toolkit.config import FeatureLevelConfig
from ml_toolkit.psi import PSIBaseline, PSIConfig

reference = PSIBaseline.from_reference(
    part.train.X,
    config=PSIConfig(
        features=tuple(
            FeatureLevelConfig(
                name,
                "categorical" if name in part.train.cat_features else "numerical",
            )
            for name in part.train.X.columns
        )
    ),
    time=part.train.time,
)
with TemporaryDirectory() as directory:
    reference.save(directory)
    with mlflow.start_run(run_name="psi-monitoring"):
        info = model.log(
            part.train, extra_artifacts={"psi_baseline": directory}
        )

    Use the same immutable model URI for serving and monitoring. The saved package remains available after the temporary source directory has been removed:

    from polars.testing import assert_frame_equal
from ml_toolkit.tracking import load_psi_baseline

model_uri = info.model_uri
served = mlflow.pyfunc.load_model(model_uri)
baseline = load_psi_baseline(model_uri)

# Use the original training feature representation for monitoring.
current_X = test.X
current_levels = baseline.transformer.transform(current_X)
result = baseline.compare(current_X)
assert_frame_equal(result.psi, reference.compare(current_X).psi)
np.testing.assert_allclose(
    served.predict(test.to_model_input(categorical_as_strings=True)),
    model.predict_pool(test),
)

    The loader also accepts a registered version such as models:/risk_model/17 or a local model package. It reads the named artifact from MLmodel without loading native model weights or executing serving code. Install a compatible ml-toolkit in the monitoring environment. Use a fixed model version instead of independently resolving a mutable registry alias for serving and monitoring.

    Each baseline uses all training rows after feature selection, independently of input_example_rows. Validation/test rows are excluded unless they are part of the subsequent final fit's training population. A train-only final fit still packages its baseline. Inflation-adjusted models include the same reference in both their native and wrapper packages.

    The package contains manifest.json (format version, scoring settings and reference metadata), levels.json (typed fitted transformation rules), and reference_counts.parquet (feature/level counts, including zero counts). It contains no source rows and requires no separate PyFunc model. Graphs and evaluation distributions remain run artifacts. Missing baselines raise FileNotFoundError; malformed or unsupported state raises ValueError. Existing models remain loadable for predictions without migration.
