    Migrating to 7.0¶

    Version 7.0 reorganizes the package so that every concept has one home. Mostly import paths change; the few behaviour changes are listed under "Behaviour changes" (and per phase below). Persisted classification model state is now version 2 (see "Positive-unlabeled learning"); everything else saved by 6.x is unchanged. Models and PSI baselines logged by 6.x keep loading. Old import paths are removed without compatibility aliases.

    Packaging entrypoints¶

    MLflow models-from-code entrypoints are now generated when a model is logged, so ml_toolkit.tracking.entrypoints no longer exists. Artifacts written by earlier versions contain their own entrypoint file and load unchanged.

    log_model_from_code (in ml_toolkit.models.artifacts) now takes model_class (and optionally model_module, default ml_toolkit.models) instead of source, the path of an entrypoint file. Only toolkit adapters exported from that module can be logged this way; other classes raise ValueError. Custom adapters package themselves, as in examples/custom_model.py.

    Internal checks¶

    tests/test_architecture.py enforces the layer order between modules.

    Feature selection (phase 5)¶

    ml_toolkit.feature_selection is now a package. Its public names are exported from ml_toolkit.feature_selection itself.

    Old import New import
    ml_toolkit.training.importance_ranker ml_toolkit.feature_selection.importance_ranker
    ml_toolkit.training.ShapRanker ml_toolkit.feature_selection.ShapRanker
    ml_toolkit.training.rankers ml_toolkit.feature_selection
    ml_toolkit.plots.feature_selection.* (rfe_progress, top_k_ranking, forward_progress, forward_improvement, best_iteration_progress) ml_toolkit.feature_selection.figures
    ml_toolkit.feature_selection.SelectionSettings (a dict) ml_toolkit.feature_selection.SelectionSettings, a union of RFESettings, TopKSettings, ForwardSettings and CustomSelectionSettings

    Custom selectors return CustomSelectionSettings("name", {"key": value}) instead of {"selector": "name", "key": value}. FeatureSelectionResult.settings defaults to None instead of {}.

    Behaviour changes¶

    • FeatureSelectionResult.settings is a typed dataclass: use attribute access (result.settings.k, result.settings.evaluator) instead of dictionary access. evaluator is None when unset. selection/history.json is unchanged; FeatureSelectionResult.to_dict() is the only way to build the logged payload (dataclasses.asdict nests details and keeps evaluator: null). Settings reject negative or non-finite numeric fields, and CustomSelectionSettings rejects the built-in selector names and a selector key in details.
    • GroupedMetrics now reports a metric callback that returns no scores or empty names as Metric must return nonempty named scores (previously Grouped metric must return at least one named score or Grouped metric names must be nonempty strings), the same message MetricTrend and ShrinkCurve use.
    • classification.calibration reports a nonpositive histogram_bins as histogram_bins must be positive; a nonpositive n_bins is rejected by classification.calibration_bins as n_bins must be positive (previously both gave bin counts must be positive).

    Training workflow (phase 6)¶

    train_model is split into named internal steps; training results, logged MLflow parameters, metrics and artifacts, and console output are unchanged. Each public name now has one import path.

    Old import New import
    ml_toolkit.training.TuningConfig, TrainingConfig, ReportingConfig ml_toolkit.config
    ml_toolkit.training.FeatureLevelConfig, ml_toolkit.config.FeatureLevelConfig ml_toolkit.feature_levels.FeatureLevelConfig
    ml_toolkit.config.TimePeriod ml_toolkit.types.TimePeriod
    ml_toolkit.data.validate_auxiliary_pair(left, right) ml_toolkit.data.validate_compatible_pools(left, right, context=...)

    Behaviour changes:

    • One check, validate_compatible_pools, compares feature schemas (names, order and dtypes), categorical and numerical feature declarations and auxiliary schemas. Split, concat_pools, validation fits, feature selection and the fit_on_test final fit all use it, so the messages now read <subject> must have matching features and metadata (for example Split pools, Reporting pools, Train and validation pools, Final-fit data) or ... must have matching auxiliary feature schemas; the feature check runs first, so a pair that differs in both reports the feature message. Feature selection and validation fits previously compared column names only; they now also reject differing dtypes or feature declarations between train and validation.

    Positive-unlabeled learning¶

    Old New
    params["pu_prior"] params["class_prior"]
    PUMetric(prior=...) PUMetric(class_prior=...)
    CatBoostPUClassificationModel.pu_prior CatBoostPUClassificationModel.class_prior

    Behaviour changes:

    • The estimator now treats the whole training pool as the unlabeled sample of the population; labeled rows are part of it. Results change. Values tuned for the old estimator must be revisited: a value equal to the positive share among unlabeled rows should now be replaced by the population prevalence P(y=1). PUMetric uses the same definition.
    • class_prior must be at least the weighted share of known positives in the training pool; smaller values raise ValueError.
    • nnPU trains in a single CatBoost fit instead of one fit per tree. The branch decision still follows Kiryo et al. (2017), Algorithm 1, on the full training pool before every tree; the trees differ from 7.0 development builds only because the estimator changed (see above). eval_metric must be nnPU (or unset) and metric_period must be 1. Early stopping and best-iteration selection are native CatBoost.
    • New nnPU options nnpu_beta (default 0, at least 0) and nnpu_gamma (default 0.2, in (0, 1]); they are rejected for uPU. class_prior, nnpu_beta and nnpu_gamma are rejected by CatBoostClassificationModel.
    • Classification model state is version 2 and stores class_prior. Artifacts written by 6.x keep loading (pu_prior is read as class_prior), but their stored training parameters still contain pu_prior, so refitting such a model requires renaming the parameter first.
